# TBLite "haiku-tier" quality test (OpenThoughts-TBLite, easy + medium)

Prepared 23.10.2026 on the workstation (fedora-homeamd). No model was called while preparing it. The validation runs
used Harbor's `oracle` and `nop` agents only, with no proxy, no key and nothing on xeon. Runner: `tblite.sh`. It calls the
unchanged `run-tb.sh`, so every model gets the same chain as the pilots: Claude Code 2.1.303 -> test LiteLLM proxy
:4001 -> local engine, with the same proxy checks, environment scrubbing and key redaction. General Terminal-Bench
notes (proxy, key, network audit) are in `README.md`.

## What it is

OpenThoughts-TBLite (Feb 2026, OpenThoughts-Agent team + Snorkel AI + Bespoke Labs, Apache-2.0) is a set of 100
Terminal-Bench-style tasks. Each task is a Docker image, an instruction and a pytest grader. The authors balanced the set
by Claude Haiku 4.5's pass rate: 40 easy (>= 70 %), 26 medium (40-69 %), 26 hard (10-39 %) and 8 extreme (< 10 %).
Published results (Harbor, 32 Daytona sandboxes, other agents): Haiku 4.5 64.4 % on all 100, gpt-5-mini 50.5 %,
Qwen3-235B-A22B 37.0 %. TBLite correlates with TB2 at r = 0.911. For us it is the haiku-tier quality test: tasks a
Haiku-class model mostly solves, run end to end through Claude Code like production traffic.

**The per-task Haiku labels are not published.** The HF card, the GitHub repo, the blog, the leaderboard and three
mirrors (NousResearch, junlin-modal, Virtual-Production-Units) only carry `task.toml`'s author label. Those labels split
differently: 24 easy / 43 medium / 30 hard / 3 expert. So "easy + medium" here means the **67 author-labelled
easy/medium tasks**, not the authors' 66 calibrated ones. The author label is a weak difficulty signal. In the
night-1021 runs at n=16, Flash scored 61-65 % on its easy/medium tasks and 65-78 % on its hard ones.

### Base image pin (new, 23.10.)

The Dockerfiles use moving tags. `python:3.13-slim-bookworm` (28 tasks) moved twice between 21.10. and 23.10., and four
other python tags moved once. BuildKit (the default docker builder) uses a **local** image for `FROM` when one exists and
otherwise resolves the tag at the registry. An unpinned tag therefore means a full rebuild during the GPU window, with
whatever apt/pip versions are current that day. `./tblite-prepare.sh pin` pulled each tag **by digest** and tagged it
locally. The digests are the ones the BuildKit cache was built from on 21.10. (the oracle validation and the flash-prod
and flash-b v60 baselines). Every task build is now a cache hit (4-15 s) and needs no registry lookup. I tested that
BuildKit prefers the local tag: a probe build used local `python:3.11-slim@0a236bf8`, while upstream was already at
`b7a9e5f6`. `tblite.sh` runs `tblite-prepare.sh check` before every run and aborts if a tag drifted (someone ran
`docker pull`). Fix it with `./tblite-prepare.sh pin`.

Per-trial images do not need to be kept. Harbor builds each trial from the cache and removes the image afterwards
(`compose down --rmi local`). The default builder's GC keeps cache records for 60 days while more than 347 GB of disk
is free, so the "pre-pull/build" is the pinned base images plus a warm BuildKit cache. The oracle run below rebuilt all
100 tasks from that cache.

## Task set

`tblite-tasks.tsv` (generated by `tools/tblite_tasks.py`) has one row per task: author difficulty, validation status,
agent timeout, oracle reward and public solves.

| difficulty | oracle (ref = 1.0) | oracle-partial | public-solved | unverified | broken | total |
|---|---|---|---|---|---|---|
| easy | 18 | 0 | 2 | 1 | 3 | 24 |
| medium | 24 | 3 | 11 | 2 | 3 | 43 |
| hard | 14 | 1 | 7 | 1 | 7 | 30 |
| expert | 0 | 0 | 1 | 1 | 1 | 3 |

What each status means:

* **oracle**: the shipped reference solution scores 1.0 here, in identical runs on 21.10. and 23.10.
* **oracle-partial**: the reference itself only gets partial credit. In the default set these are
  security-breach-incident-response 0.75, security-incident-log-analysis 0.92 and tsl-test-case-generation 0.88.
* **public-solved**: the task ships no reference (`solve.sh` only prints "no solution written"), so the oracle cannot
  show it is solvable here. A public Terminus-2 trial did score 1.0 on it (gemini-2.5-flash or gpt-5-nano, March 2026;
  HF `DCAgent/eval__openthoughts-tblite__*`). That means the grader can award full credit (`tblite-public-solves.tsv`).
* **unverified**: no reference, and no public trial solved it. The easy/medium ones are grpc-plant-position-server,
  legal-summary-extraction and sympy-bug-fix (0/6, 0/5 and 0/3 public trials).
* **broken**: the reference fails here (`tblite-exclude-broken.txt`). The easy/medium ones are amuse-install,
  protein-sequence, smiles-data-lab, git-repo-forensics, okhttp-trailers-crash and sql-injection-forensics.

**Default set = easy + medium, statuses oracle + oracle-partial + public-solved = 58 tasks** (20 easy, 38 medium).
The sum of agent timeouts is 27.6 h, and 13 of the tasks have a 60 min timeout.

## Commands per candidate (GPU window)

Run one model at a time. Bring the engine up on xeon with the candidate's kit (`~/gpu/xeon-bench/speed/haiku-1021/*.md`),
then point the test proxy at it. Give `--engine` every time. The alias `claude-sonnet-4-5` is the same for every model,
and `tblite.sh` aborts if the proxy routes it to a different served model. The default alias is `claude-sonnet-4-5`
(cc-sonnet tier, effort medium), the same as every pilot. `--model claude-haiku-4-5` would test the low-effort haiku
tier instead.

```bash
# Flash-Next (TEST engine radiance-flash-kvtest :8091, MAXSEQS 8 -> keep n=8)
cd ~/litellm-test && ./run.sh flash --all-parallel 32
cd ~/gpu/tbench && ./tblite.sh flash --engine qwen3.8-flash-next

# Sabi-Noema (DP2 :8094/:8095)
cd ~/litellm-test && ./run.sh sabi --sabi-model sabi-noema --all-parallel 32
cd ~/gpu/tbench && ./tblite.sh sabi --engine sabi-noema

# Sage-A1.5 (DP2 :8094/:8095)
cd ~/litellm-test && ./run.sh sabi --sabi-model sage-a1.5 --all-parallel 32
cd ~/gpu/tbench && ./tblite.sh sage --engine sage-a1.5

# Flint: Claude Code needs the SPLIT layout (dp2 slots are 30k); both proxy backends = the one server (FLINT.md step 6)
cd ~/litellm-test && ./run.sh sabi --sabi-model flint --all-parallel 32 --sabi-b http://<tailscale-ip>:8094/v1 --max-input-tokens 114000
cd ~/gpu/tbench && ./tblite.sh flint --engine flint

# Raon-1 mini (llama.cpp DP2, 96k slots)
cd ~/litellm-test && ./run.sh sabi --sabi-model raon-1-mini --all-parallel 32 --max-input-tokens 80000
cd ~/gpu/tbench && ./tblite.sh raon --engine raon-1-mini

# afterwards / any time: comparison table (also rewritten after every model run)
cd ~/gpu/tbench && ./tblite.sh --compare            # -> runs/tblite-compare.md
cd ~/litellm-test && ./run.sh sabi                   # restore the default test config when done; ./stop.sh to stop
```

* Run directory: `runs/tblite-<label>-<YYYYmmdd-HHMM>/`. It contains `run-meta.json` (run-tb.sh's meta plus a `tblite`
  block with the subset, pins and argv), `tasks.txt`, `summary.md`, `summary-tbsummary.md` (the pilot format),
  `harbor.log` and `proxy.log`.
* `summary.md` reports:
  * score (mean reward) with a bootstrap CI, and strict pass with a Wilson CI;
  * the score on oracle-verified tasks only;
  * timeouts, including how many still scored 1;
  * agent minutes (median, mean, p90, max, sum), non-agent minutes, and tokens per trial (in/cached/out);
  * proxy failures and non-local deployments;
  * tables by difficulty (with Wilson CI) and by validation status, and a per-task table.
* `runs/tblite-compare.md` has one row per model run: score, strict + Wilson CI, easy, medium, oracle-verified,
  timeouts, agent minutes, wall time and tokens/trial. It also gives the paired Δ vs Flash (bootstrap CI over common
  tasks) and wins/losses with an exact McNemar p.
* An interrupted run resumes with `./tblite.sh --resume runs/tblite-<label>-<time>`.
* `--dry-run` prints the task list and the plan.
* `tblite.sh` refuses to start while another Harbor job runs on the workstation, because shared CPU and Docker skew
  wall-clock timeouts. Override with `--allow-concurrent`.

## Expected wall time per model (n=8, default 58 tasks)

`tools/tblite_estimate.py <pilot run dirs>` computes these from measured data only:

* Flash's per-task agent minutes in the night-1021 v60 runs (n=16), scaled to n=8 by Flash's pilot10 ratio (×0.47,
  because at n=16 the engine queued on MAXSEQS 8);
* the model's pilot10 agent-minute sum relative to Flash's;
* the oracle run's build/verify overhead;
* list scheduling over 8 slots.

"Optimistic" scales every task. "Conservative" keeps the full timeout for the tasks where Flash timed out in v60 (about
half of them).

| model (pilot) | pilot score | pilot agent-min | default 58: optimistic / conservative (p90) | verified 45: optimistic / conservative (p90) |
|---|---|---|---|---|
| Flash-Next (flash-pilot10-cc) | 10/10 | 39.5 | 0.95 / 1.52 (1.98) h | 0.70 / 1.39 (1.76) h |
| Sabi-Noema (sabi-pilot10-cc) | 8/10 | 42.3 | 1.01 / 1.53 (2.00) h | 0.74 / 1.40 (1.77) h |
| Sage-A1.5 (sage-pilot10-cc) | 5/10 | 67.7 | 1.58 / 1.78 (2.22) h | 1.17 / 1.44 (1.84) h |
| Flint, Raon | pilots running 23.10. | | after the pilot: `tools/tblite_estimate.py runs/<pilot>` | |
| upper bound (every trial times out) | | | 4.02 h | 2.40 h |

Reference points:

* Flash's v60 run at n=16 took 1.37 h for 60 tasks, with 31/60 agent timeouts.
* At n=8, plan **~1-1.5 h per model** (p90 ~2 h) for the default set. A dense or slow model adds ~0.3 h.
* Wall time can never be shorter than the longest trial (60 min tasks).
* One model at n=8 plus the engine switch is about 1.5-2.5 h of GPU window, so three models need about a 5-7 h window.
* The 45-task `--verified-only` set saves about 15-30 min per model. The 13 public-solved tasks cost about 13 h of
  timeout budget.

## Caveats

* **Contamination.** The tasks have been public since Feb 2026 (GitHub, HF; canary GUID in every instruction). Full
  public agent trajectories for these exact tasks are on HF (`DCAgent/eval__openthoughts-tblite__*`, hundreds of trials
  per model), as is OpenThoughts-Agent training data. RL and agentic fine-tunes from 2026 (Sabi-Noema, Sage-A1.5, Flint,
  Raon) may have seen tasks or solutions. Compare models with each other only. A pass with unusually few tokens on a
  long task is worth a look in the per-task table.
* **Not comparable to published TBLite numbers.** We run a subset, Claude Code through our proxy, on local Docker,
  with the author labels.
* **Speed confounds quality.** Agent timeouts are wall-clock. A slower engine, or a larger n, gets fewer turns. Flash at
  n=16 timed out on about half of its trials, and 12 of those 31 still scored 1 (the grader checks the files). Keep
  n=8 for every model, and keep the engine's concurrency (MAXSEQS / slots) >= n: the Flash test container has MAXSEQS 8.
  For quality without speed, use `--timeout-mult 2`, which doubles the upper bound.
* **Context limits.** Claude Code thinks `claude-sonnet-4-5` has 200k context. Raon (80k max input) and Flint
  (114k split, 30k dp2) cannot hold long sessions, and the overflow shows up as request errors or zero rewards. That is
  a real serving limit of those layouts, but report it with the score.
* **Statistical power.** 58 tasks × 1 attempt gives a Wilson half-width of about ±12 pp. Differences below about 15 pp
  need the paired column in `tblite-compare.md` or `--attempts 2-3` for the finalists. Haiku-calibrated tasks are
  stochastic by design: a 40-69 % "medium" task flips between attempts.
* **Task flakiness.** The graders are deterministic for the reference solutions: 100/100 identical rewards on 21.10.
  and 23.10. Three default tasks give partial credit. The 13 public-solved tasks are graded here but were never solved
  here. Their builds and graders run and score an empty answer 0 (nop run), but their solvability rests on public
  March 2026 runs. The summary reports the oracle-verified score separately for that reason.
* **Docker and network needs.** Docker on the workstation (no sudo needed), about 6 GB of pinned base images, and the
  BuildKit cache, which already holds the layers. Internet is needed during runs: verifiers download pytest/uv, and
  agents use pip/apt. A network outage turns into false failures. Do not run `docker builder prune` or
  `docker system prune`: it drops the cache, and the next run rebuilds everything with that day's packages. A
  `docker pull` of a pinned tag is caught by the check.
* **Workstation memory.** The workstation hard-hung once under a TB n=16 run (22.10., see night-quality-1022).
  Stay at n=8.
* **Docker network pool (24.10.).** Every trial gets its own compose network. The workstation Docker uses the default
  address pools (31 subnets), and bridge, litellm_default and litellm-test_default take 3 of them. Above ~28 trials,
  `docker compose up` fails with "all predefined address pools have been fully subnetted" and the trial ends as a
  RuntimeError before the model runs. The n=32 try on 24.10. lost 28 trials in 2 min this way. The haiku window ran at
  n=24. Going higher needs `default-address-pools` in /etc/docker/daemon.json and a Docker restart (sudo; production
  LiteLLM restarts too).
* **Auxiliary calls.** The proxy routes Claude Code's auxiliary-class requests to `cc-aux`, which is a cloud model. The
  pilots had none. `summary.md` flags any non-local deployment. Check that row after each run.
* **Proxy dedication.** `proxy.log` holds every request in the run window, so keep the test proxy dedicated during a run.

* **Affinity burst (24.10.).** At a TBLite start all n sessions open within one metrics poll (5 s) of the test proxy's
  qwen_affinity, so every first turn sees the same snapshot. A residual KV of 3e-5 on b sent all 24 first turns of
  the Ornith run to a (16 running + 5 waiting on GPU1, 3 on GPU2); that run was aborted after 10 min and archived as
  `runs/tblite-ornith-20261024-1909.aborted`. Sage's run was balanced (exact-zero tie -> session-hash parity).
  Fix (test proxy only, `hint_logger_shim.py`, backup `.bak-20261024-burst`): each new placement counts as one running
  request on its side for 10 s (`QWENAFF_BURST=0` = production behaviour). Check the a/b split in the first minutes.
