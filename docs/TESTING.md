RULES:
1. An open-loop replay pair compares arms only while both ran the reference's load, which means small levers on one image and A/A.
2. `--pair-replay` now prints `validity`: per-arm overlaps (VALID needs <= 5 % of the kept turns in each arm) and the uncached-token ratio (0.9-1.1). On these: 135 VALID (3 / 4, 1.0016); 139 INVALID (155 / 2, 0.504). A pair reported INVALID is not read.
3. Arms of unequal capacity (a different line, MNBT / span or another config change, any lever that can move capacity more than a few %) use `--replay-closed`, closed-loop per user. A user's first request goes at the reference's start time; each later one goes when that user's previous reply has ended in THIS run, plus the reference's gap after it (its think / tool time). The prompts stay identical request for request, and each user has at most one request in flight, as in the reference.
4. Alternatively, record the reference on the slower arm.
5. Closed-loop arrivals follow each arm's speed, so makespan and requests a minute become a throughput read as well. Its own A/A floor comes first: no closed-loop pair is read before it.

Mock smoke test (local, 16 users, a 0.4 s-latency stub, the reference's times / 100): open-loop overlap 192 of 192, mean in-flight 15.9; closed-loop overlap 0, in-flight 7.85; prompt tokens identical (11.74 M both).

**13.11.2026 METHOD LESSONS from Qwen G16q (fn4 213 / 217; coordinator: every agent uses these):**
1. SMALL DECODE LEVERS ARE JUDGED ON THE STEP-LOG FULL-ROW BUCKET, not on mb tok/s. Start with `RADIANCE_LOG_STEPS=1`, take the engine log with `docker logs -t`, and read the p50 step ms of the full-row steps per block: n_seq = c and n_tok = c x (1 + n_spec), e.g. Qwen 64-row steps at c16, 32-row at c8 (a step's ms = the next step line's time minus its own). Tools: `queue-ar/tools/fnsteps.py LOG --blocks BLOCKS.jsonl --label L:SEQS:ROWS` (abblocks2 blocks, by applied_step; B/A of block p50s, round ratios, separation) and DS `dsmain/prof12/p12win.py rows`. Block p50 spread measured 0.1-0.3 % (217: c16 37.65 / 37.83 / 37.90 / 37.89 ms for one arm), against 2-6 % for mb blocks. Use ABBAABBA where more blocks are needed. Example: 213 read G16q as "no measurable change" on mb (c16 B/A 0.974, overlapping blocks); 217's step log showed +2.0 % a full-row step at c16 and c8, with every block separated.
2. MEMORY-BOUND KERNEL FORMS (hc_read and similar weight-streaming ops) ARE CHOSEN ON A COLD MICROBENCH plus the engine step log, never on the warm microbench alone. A warm loop (`r4d_selftest --perfX M iters` relaunching on the same weights) keeps them in L2 / MALL. In the engine each of the ~96 reads a step finds its own weights cold. Time both warm and `--cold 256` (a 256 MiB read through the hierarchy before each launch, median), and confirm in the engine with the step log (1.) before a form joins a base. Example: G16q was -10..-24 % against G16 warm (x22), but +2.0 % a full-row step in the engine (217). The cold check is xeon x26.
3. ENGAGEMENT: before reading a form or lever A/B, prove that it ran. Read back the switch (GET /admin/fn4) and count calls per form, e.g. libr4d's `RADIANCE_FN4_FORMCTR=1` (hc_read forms a device, stderr lines, `fnsteps.py` attributes them per block).
